# Excel Export — Design Spec
Date: 2026-05-25
Project: Proba1 (USPP METAR мониторинг ВПП)

## Что делаем

Кнопка "Экспорт" на странице — нажатие сразу запускает скачивание .xlsx файла за выбранный диапазон дат.

## Сервер

### Новый эндпоинт

```
GET /api/export?from=<ISO UTC>&to=<ISO UTC>
```

- Обработчик `export_handler` в `server.py`
- Зависимость: `openpyxl` (установить через pip)
- Файл формируется в памяти (BytesIO), без временных файлов
- Ответ: `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- Имя файла: `USPP_YYYYMMDD_YYYYMMDD.xlsx` — только дата из `from`/`to` (первые 10 символов ISO → убрать `-`), без времени и спецсимволов. Пример: `USPP_20260523_20260525.xlsx`
- Данные: те же запросы к SQLite что в `history_handler` и `stats_handler`, без лимита строк
- SQLite открывается с `check_same_thread=False`; БД работает в режиме WAL (`PRAGMA journal_mode=WAL`) — конкурентные чтения (экспорт) и записи (сборщик METAR) не блокируют друг друга
- Строки отсортированы по `ts ASC`

### Структура .xlsx

**Лист 1 — "Данные"**

| № | Время (UTC) | ВПП | Курс (°) | Откуда (°) | Скорость (уз) | Порыв (уз) | Штиль | Переменный | METAR |
|---|---|---|---|---|---|---|---|---|---|

Источник колонок из DB: `ts`, `runway`, `heading`, `wind_dir`, `wind_spd`, `wind_gst`, `is_calm` (0/1 → Нет/Да), `is_vrb` (0/1 → Нет/Да), `raw_metar`

**Лист 2 — "Статистика"**

| Параметр | Значение |
|---|---|
| Период с | <from> |
| Период по | <to> |
| Всего записей | N |
| ВПП 21 | count (X%) |
| ВПП 03 | count (X%) |

## Фронтенд

- Кнопка **"Экспорт"** рядом с кнопкой "Загрузить" в секции "История из базы данных"
- При клике формирует URL `/api/export?from=...&to=...` из текущих значений `fromDt` и `toDt` (те же UTC-значения что используются в `loadDB()`)
- Открывает URL через `window.location.href` — браузер сам скачивает файл
- Кнопка активна всегда (не блокируется при загрузке)

## Валидация на сервере

| Ситуация | HTTP | Тело ответа |
|---|---|---|
| `from` или `to` отсутствует | 400 | `{"error": "from and to are required"}` |
| Невалидный формат даты | 400 | `{"error": "invalid date format, use ISO 8601"}` |
| `from > to` | 400 | `{"error": "from must be before to"}` |
| Диапазон > 90 дней | 400 | `{"error": "range must not exceed 90 days"}` |
| Ошибка SQLite | 500 | `{"error": "database error"}` |

SQL-запросы используют параметризованные плейсхолдеры `?` — прямая подстановка `from`/`to` в строку запроса запрещена.

## NULL-значения в ячейках Excel

| Поле DB | Значение NULL | В ячейке Excel |
|---|---|---|
| `wind_gst` | NULL | пустая ячейка (None) |
| `wind_dir` | NULL (при is_calm или is_vrb) | пустая ячейка |
| `heading` | NULL | пустая ячейка |

Числовые колонки (`wind_spd`, `wind_gst`, `wind_dir`, `heading`) — тип **number** в xlsx (не строка), чтобы Excel воспринимал их как числа для формул.
Булевы колонки (`is_calm`, `is_vrb`) — значения `"Да"` / `"Нет"` (строка).

## Ограничения

- Максимальный диапазон: **90 дней** — при превышении сервер возвращает 400
- Если `from`/`to` не выбраны на фронтенде — кнопка показывает `alert('Выберите период')`
- Эндпоинт публичный (авторизация не требуется — данные METAR открытые)
- Логирование: при ошибке пишем `print(f'[ERROR] export: {e}')` в stdout; входные параметры `from`/`to` не логируются
- Производительность: 90 дней × 96 записей/день (раз в 15 мин) = макс ~8 640 строк — генерация xlsx занимает < 1 сек, отдельный таймаут не нужен
